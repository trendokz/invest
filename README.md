# Trendo Analytics · инвестиционный пул

Статический сайт для инвестиционного пула Trendo Analytics: e-commerce на Kaspi.kz, где инвесторы получают долю чистой прибыли пропорционально своему капиталу.

В проекте две независимые страницы:

| Папка | Для кого | Что показывает |
|---|---|---|
| [`cabinet/`](cabinet/) | действующие инвесторы и управляющий | Личный кабинет. Вход по коду. Капитал, доля в пуле, доход за месяц с пошаговым расчётом, движение капитала, история по месяцам, графики, отчёт пула. Управляющий видит таблицу всех инвесторов и может открыть кабинет любого. |
| [`calculator/`](calculator/) | потенциальные инвесторы | Публичная страница. Результаты пула по месяцам, отчёт за месяц, калькулятор «сколько бы вы заработали» по фактической доходности. Данных отдельных инвесторов нет. |

Нет ни фреймворков, ни зависимостей, ни бэкенда. Каждая страница — один HTML-файл с встроенными CSS, JS и данными. Внешние ресурсы: только шрифты Google Fonts (Montserrat, Inter).

## Конфигурация

Настройки задаются в `.env` (в git не попадает). Шаблон с тестовыми значениями — [`.env.example`](.env.example):

```bash
cp .env.example .env
```

| Переменная | По умолчанию | Описание |
|---|---|---|
| `TRENDO_DATA_DIR` | `./example` | папка с `data.json` и `codes.json` |
| `TRENDO_PORT` | `8080` | порт сайта (Docker) |

- **Разработка и тесты:** `TRENDO_DATA_DIR=./example` — вымышленный инвестор из репозитория. Коды: `AB-1234` (инвестор), `ADMIN-CODE` (управляющий).
- **Продакшен:** реальные `data.json` и `codes.json` **не хранятся в git**. Их передаёт владелец проекта отдельно (зашифрованный архив или менеджер паролей). Положите их в папку вне репозитория или в `private/` (она в `.gitignore`) и укажите путь в `TRENDO_DATA_DIR`.

## Запуск через Docker

```bash
git clone https://github.com/trendokz/invest.git
cd invest
cp .env.example .env        # при необходимости поменяйте TRENDO_DATA_DIR
docker compose up -d
```

Откройте http://localhost:8080:

- `/calculator/` — страница для потенциальных инвесторов (главная ведёт сюда);
- `/cabinet/` — кабинет инвестора.

После изменения данных пересоберите:

```bash
docker compose up -d --force-recreate
```

Как устроено: контейнер `build` (`python:3.12-alpine`) запускает `build.py` и складывает готовые страницы в общий том, контейнер `web` (`nginx:1.27-alpine`) их раздаёт. Папка `TRENDO_DATA_DIR` подключается только как том на чтение и не попадает в образы. В `docker/nginx.conf` кабинет отдаётся с `noindex` и без кэша. Для продакшена поставьте перед ним HTTPS (Caddy, Traefik или nginx с Let's Encrypt).

## Без Docker

```bash
cp .env.example .env
python3 build.py
```

Нужен только Python 3.8+, без сторонних пакетов. Результат:

```
dist/
├── index.html          главная → перенаправляет на calculator/
├── robots.txt          запрещает индексировать кабинет
├── calculator/index.html
└── cabinet/index.html  (содержит данные из TRENDO_DATA_DIR, в git не попадает)
```

На хостинг выкладывается **только содержимое `dist/`**, корень сайта должен указывать на неё (иначе главная отдаёт 404). GitHub Pages не подходит: сайт Pages публичный, даже если репозиторий приватный.

### Как работает сборка

`build.py` подставляет данные в шаблоны вместо плейсхолдеров:

- `cabinet/template.html`: `/*DATA*/null` → весь `data.json`, `/*CODES*/null` → коды инвесторов, `/*ADMIN*/null` → код управляющего.
- `calculator/template.html`: `/*STYLE*/` и `/*HELPERS*/` вырезаются из шаблона кабинета (общие стили, логотип, форматирование, блок отчёта пула, калькулятор), `/*DATA*/null` → только данные пула **без инвесторов**.

После сборки скрипт проверяет, что в `calculator/index.html` нет имён инвесторов, кодов и ключа `investors`. Если что-то просочилось, сборка падает.

Общий код вырезается из `cabinet/template.html` по маркерам (`const LOGO`, `function poolBlock`, `const RATE`, `function drawCalc` и т. д.). При рефакторинге шаблона кабинета эти маркеры нужно сохранить или обновить `build.py`.

## Формат данных (`data.json`)

Полный пример в [`example/data.json`](example/data.json).

```jsonc
{
  "investors": [                         // справочник инвесторов
    { "id": "inv1", "name": "Имя", "start": "2025-10-25", "initial": 1000000 }
  ],
  "months": [ /* месяцы по порядку, от старых к новым */ ]
}
```

### Месяц

| Поле | Тип | Описание |
|---|---|---|
| `key` | `"2026-09"` | идентификатор месяца |
| `label` | `"Сентябрь 2026"` | подпись (первое слово используется как название месяца) |
| `period` | `"1–30 сентября 2026"` | период отчёта |
| `orders`, `returns` | число | заказы и возвраты за месяц |
| `periods` | массив | отрезки месяца с постоянным капиталом пула (см. ниже) |
| `pool` | объект | P&L пула: `sales`, `cogs`, `kaspi`, `delivery`, `tax`, `gross`, `expenses`, `net`, `capital`, `skus` |
| `expenses` | `[["Маркетинг", 1477875], …]` | операционные расходы, по убыванию |
| `top` | массив | лучшие товары: `name`, `qty`, `sales`, `profit` |
| `investors` | массив | строки инвесторов за месяц (см. ниже) |

### Периоды внутри месяца

Если в середине месяца кто-то вносит или выводит деньги, месяц делится на отрезки, и прибыль каждого отрезка делится по капиталу этого отрезка:

```json
"periods": [
  { "label": "1–20 июля",  "days": 20, "net": 3173645, "capital": 38102472 },
  { "label": "21–31 июля", "days": 11, "net": 1745505, "capital": 34102472 }
]
```

`net` отрезка = чистая прибыль месяца ÷ дней в месяце × дней в отрезке.

### Строка инвестора за месяц

| Поле | Описание |
|---|---|
| `id` | ссылка на `investors[].id` |
| `rate` | доля инвестора в прибыли на его капитал: обычно `0.5`, может быть индивидуальной |
| `parts` | по одному на каждый период: `capital`, `share` (доля в пуле), `profit` (прибыль пула на эту долю) |
| `capitalStart`, `capitalEnd` | капитал на начало и конец месяца |
| `dividend` | доход инвестора за месяц = Σ `parts[].profit` × `rate` |
| `yield_` | доходность за месяц (доля, не проценты) |
| `initial` | первоначальные вложения |
| `totalProfit` | прибыль за всё время, накопительно |
| `roi`, `months`, `avgMonthly` | ROI, срок в пуле, средняя доходность в месяц |
| `flows` | движение капитала: `{label, amount, paid?, info?}`. `paid: true` — дивиденд выплачен, а не реинвестирован |

Цифры берутся из итогового блока ежемесячного Excel-отчёта управляющих как есть, без пересчёта.

## Бизнес-правила

- Чистая прибыль пула = валовая прибыль − операционные расходы.
- Доля инвестора = его капитал ÷ капитал пула (в каждом периоде).
- Доход инвестора = прибыль пула × доля × `rate` (стандартно 50%, остальное получают управляющие).
- Новые деньги начинают участвовать в прибыли через **25 дней** после взноса: время на аналитику, закуп и логистику.
- Дивиденд можно реинвестировать (капитал растёт) или забрать (капитал не меняется).
- Калькулятор: доходность инвестора за месяц = `0.5 × Σ(period.net / period.capital)`. Режим «реинвест» считает сложный процент, режим «забирать» — простой.

## Ежемесячное обновление

1. Добавить новый объект в конец `data.json → months` (в папке `TRENDO_DATA_DIR`) по данным из Excel-отчёта.
2. Новому инвестору добавить запись в `investors` и код в `codes.json`.
3. `python3 build.py` или `docker compose up -d --force-recreate`.
4. Закоммитить изменения.

Новый месяц автоматически появится в переключателе месяцев, графиках, истории и калькуляторе.

## Безопасность (важно)

**Текущая защита кабинета — только для демонстрации.** Коды проверяются в браузере, а в `cabinet/index.html` лежат данные **всех** инвесторов и все коды. Любой, кто получит этот файл, увидит всё.

Поэтому:

- Реальные данные и коды не хранятся в git: `.env`, `private/`, `cabinet/index.html` и `dist/cabinet/` в `.gitignore`. В репозитории только код и вымышленные данные из `example/`.
- `calculator/index.html` безопасен для публикации (GitHub Pages, любой хостинг).

### Что нужно для продакшена

Кабинет должен отдавать каждому инвестору **только его данные** после авторизации на сервере. Минимальный вариант:

1. Бэкенд (любой: Node/Express, Python/FastAPI, Firebase/Supabase) с таблицами `investors`, `months`, `investor_months`. Схема повторяет `data.json`.
2. Авторизация: логин (телефон или email) + пароль или одноразовый код. Роль `admin` для управляющих.
3. API: `GET /api/me` → строки только текущего инвестора + общие данные пула; `GET /api/admin/...` → только для роли admin.
4. Фронтенд: `cabinet/template.html` уже разделён на функции рендера (`investorView`, `adminView`, `poolBlock`, `calcSteps`, `flowsBlock`, `historyBlock`, графики). Вместо встроенного `DATA` их можно кормить ответом API.
5. Загрузка месяца: импорт Excel-отчёта или ручной ввод в админке вместо правки `data.json`.

## Дизайн

- Фирменные цвета: тёмно-синий фон, золото для денег и акцентов, серебро для вспомогательных элементов. Все цвета заданы токенами в `:root` в начале `cabinet/template.html`.
- Шрифты: Montserrat (заголовки, цифры), Inter (текст).
- Логотип нарисован векторно (SVG) в константе `LOGO`.
- Адаптивная вёрстка: от 360px до десктопа.
